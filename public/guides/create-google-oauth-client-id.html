How to create a Google OAuth client ID

Guide · last updated 20 November 2026

Gmail Storage Lens does not use a shared Google sign-in client. You create one in your own Google Cloud project, and the app signs in with it. This keeps your access under your control. This guide explains the idea in plain language and then lists the steps.

What is a client ID, and why do you need one?

When an app asks Google for access to your Gmail or Drive, Google needs to know which app is asking. An OAuth client ID is the public identifier for that app. It is not a password and it does not give anyone access to your account on its own. Access is granted only when you sign in and agree to the permissions.

Google requires apps that read Gmail and Drive to be verified before the public can use them. Creating your own client for your own account avoids that process, and it means the project maintainers never handle your credentials.

Never create or paste a client secret for this app. Gmail Storage Lens does not need one. If a screen asks for a secret while you are setting it up, you are probably on the wrong screen or the wrong client type.

What you will need

  • A Google account you are allowed to use with third-party apps.
  • About five minutes.
  • The web address you will open the app from. For the live site, this is https://shuvam-banerji-seal.github.io. For a local copy, it is http://localhost:5173.

You do not need to enter billing details for this setup.

The steps

  1. Create a project. Open Google Cloud's project page, enter a name such as storage-lens, and create it. Make sure the new project is selected at the top of the console.
  2. Enable two APIs. Open the Gmail API and Google Drive API pages in the console and choose Enable on each one.
  3. Set up the Google Auth Platform. Under Branding, give the app a name and your contact email. Under Audience, choose External, keep the status at Testing, and add your own Google account under Test users.
  4. Create a client. Open Clients, choose Create client, and select Web application. Under Authorized JavaScript origins, add the origin only. Enter it with no path and no trailing slash. Leave Authorized redirect URIs empty.
  5. Copy the Client ID. It looks like 123456789-abc...apps.googleusercontent.com. Copy it and paste it into the app.

Common mistakes

  • Adding a path to the origin. Use https://your-name.github.io, not a path that includes the project name.
  • Forgetting to add yourself as a test user. Only test users can sign in while the app is in Testing mode.
  • Choosing the wrong client type. Use Web application.
  • Forgetting to enable an API. Sign-in can succeed while the scan then fails with a message that the API is not enabled.

What to expect when you sign in

Google may show a warning that the app has not been verified. This is normal for an app you created yourself in Testing mode. Choose the option to continue, which may be behind an Advanced link, and then review the permissions. The app asks for read-only access first. It asks for more only when you choose an action that needs it.

When something goes wrong

  • origin_mismatch: the address you opened the app from is not listed as an authorized origin. Add the exact origin.
  • access_denied: your account is not a test user. Add it under Audience.
  • accessNotConfigured: the API is not enabled in this project. Enable it.
  • admin_policy_enforced: an administrator of your work or school account blocks the app. Ask them, or use a personal account.

The full troubleshooting table is in the project's setup guide in the repository.

Removing your client later

To remove the app's access to your account, visit your Google account's permissions page and remove the app. To delete your client, open its page in the Google Cloud console and delete it. You can also clear the app's stored data in your browser.

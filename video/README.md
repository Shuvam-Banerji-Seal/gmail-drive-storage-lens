# The teaser film

A 58-second, 1080p, narrated film that introduces Gmail Storage Lens. It is built the same way as the app: HTML, SVG and
JavaScript, with the audio generated in code. There is no stock footage, no sample library and no screen recording.

- **Watch it:** [`public/media/gmail-storage-lens-teaser.mp4`](../public/media/gmail-storage-lens-teaser.mp4) (also on the
  [live site](https://shuvam-banerji-seal.github.io/gmail-drive-storage-lens/) and in the main README).
- **Story:** the capacity bar overflows, Drive is a sliver, the weight is Gmail, the same attachment is stored again in every
  reply, Google never says why → the product → no server, your own client → senders, rivers, tides → lasso, twins, ghosts →
  the airlock → free, open source, verifiable → one closing line.
- **Design:** the "star atlas" look of the app: ink-navy plates, a coordinate grid, hairlines, mono labels and Fraunces
  display type. No gradients, no glow, no highlighted boxes. Plates are numbered like figures in an atlas.

## How it is put together

One file, `build/timeline.json`, drives everything, so picture, music and sound effects cannot drift apart.

| Path | What it does |
|---|---|
| `narration.txt` | The ten narration lines |
| `tools/align_vo.py` | Word-by-word forced alignment of the narration, plus a speech-recognition round trip (word error rate per line) |
| `tools/plan.mjs` | Lays the lines out on a quarter-second grid and resolves named cues (a cue is a spoken word, e.g. `lasso`) to seconds |
| `src/` | The film: `lib.js` (toolkit), `main.js` (engine, scan-line wipes, captions, chrome) and one file per scene in `src/scenes/` |
| `tools/render.mjs` | Renders every frame with headless Chromium: frame *n* is `window.__seek(n / 30)`, so the render is deterministic |
| `tools/music.py` | The score and sound effects (additive and FM synthesis, filtered noise, convolution reverb); keyed to the same cues |
| `tools/mix.mjs`, `tools/check_audio.py` | Places the voice, ducks music and effects under it, sets loudness (-16 LUFS), and checks voice-over-music in the speech band |
| `tools/encode.sh` | x264 + AAC, BT.709, faststart; also extracts the poster |
| `data/` | The committed alignment (`words.json`) and timeline (`timeline.json`) |
| `fonts/` | Fraunces and IBM Plex (SIL Open Font License), self-hosted |

Preview in a browser while editing: `node video/tools/serve.mjs`, then open the printed URL (`?play` runs in real time;
space pauses, arrows seek; `?t=12.5` shows one moment).

## Rebuilding

Needs Node 24, `ffmpeg`, Python 3 with `numpy`, `scipy` and `soundfile`, and Playwright's Chromium
(`npx playwright install chromium`).

```sh
npm ci
npm run video:plan      # timeline from video/data/words.json
npm run video:render    # 1,748 PNG frames in video/build/frames (about a minute on 8 cores)
npm run video:music     # video/build/audio/bed.wav and fx.wav
npm run video:mix       # needs the narration WAVs in video/build/vo (see below)
npm run video:encode    # public/media/gmail-storage-lens-teaser.mp4 and the poster
```

### The narration

The voice is synthetic speech from [Breeze-TTS-2](https://huggingface.co/BreezeBlue/Breeze-TTS-2) in a narrator voice that
was itself designed from a text description (it is not a recording or a clone of a real person). Synthesis runs locally on
the CPU; the repository does not ship the model or the WAV files. To regenerate them, run Breeze-TTS-2 on
`narration.txt` (one WAV per line, `line_000.wav` …) into `video/build/vo/`, then align and check:

```sh
python -E -s video/tools/align_vo.py video/build/vo video/narration.txt <path-to-breeze-tts-root>
```

`align_vo.py` reuses the CTC aligner and Whisper checkpoint from the Breeze-TTS tooling; read its header for the exact
arguments. Lines were checked by a speech-recognition round trip: eight of ten come back with no errors, and the other two
differ only by "Drive"/"drive" and "Starred"/"Star" (the model drops the final "-ed").

## What the film claims

- The numbers on screen (21.7 GiB of 20.0, 1,606 emails, 136 selected, …) are **illustrative**: the same synthetic dataset
  as the app's demo mode. The film says so on screen.
- It says Google *never tells you why* storage is full. It does not claim that bulk deletion is impossible: Gmail can
  delete a whole search result, but nothing breaks the total down by sender, thread and attachment.
